# Kubernetes tour

A guided discovery of a Kubernetes tenant, with the outputs of a test deployment. Addresses outside the cluster network are replaced with documentation addresses; the outputs are regenerated by [`tests/tour/capture.py`](../../tests/tour/capture.py) after each test cycle.

Access: the kubeconfig of the cluster (`/opt/platform/<cluster>.kubeconfig` on the bootstrap instance), from an administration source admitted on the API.

## Where am I, who am I

The kubeconfig points at the API floating IP on the administration network; its user is the cluster administrator created by kubeadm.

```console
$ kubectl cluster-info
Kubernetes control plane is running at https://192.0.2.1:6443
CoreDNS is running at https://192.0.2.1:6443/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy

To further debug and diagnose cluster problems, use 'kubectl cluster-info dump'.
```

## How it is exposed

Each `LoadBalancer` Service is an Octavia load balancer created by the cloud controller manager; its floating IP, on the plane it is published on, is created by the stack and requested by the Service.

```console
$ kubectl get svc -A --field-selector spec.type=LoadBalancer
NAMESPACE   NAME      TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)                      AGE
traefik     traefik   LoadBalancer   10.107.226.75   198.51.100.1   80:31245/TCP,443:30998/TCP   24m
```
